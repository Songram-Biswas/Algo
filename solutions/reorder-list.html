    Reorder List

    Medium Linked List Two Pointers
    LeetCode ↗

    You are given the head of a singly linked list. The list can be represented as L0 → L1 → … → Ln-1 → Ln. Reorder it in place to the form L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …

    You may not modify the values in the list's nodes — only the nodes themselves may be rearranged.

    Input: head = [1,2,3,4,5]

    Output: [1,5,2,4,3] // weave front and back halves together

    Idea

    Break this into three well-known sub-problems and chain them together. This decomposition is exactly what interviewers want to hear — it shows you can spot reusable patterns instead of inventing something ad-hoc.

    • Step 1 — Find the middle. Use slow/fast pointers. When fast reaches the end, slow sits at the middle (for even length, it lands at the start of the second half).
    • Step 2 — Reverse the second half. Split the list at slow, then reverse everything from there to the end. Now the first half is in original order and the second half is reversed.
    • Step 3 — Merge the two halves alternately. Weave nodes one-by-one: first-half node, second-half node, repeat. The second half is one node shorter or equal, so it always runs out first — stop when it does.

    Why this works: reversing the second half turns "take from the end" into "take from the front of the reversed list" — O(1) per step instead of O(n) repeated traversals to find the last remaining node.

    💡 Secret tricks for spotting complexity fast

    • Three separate O(n) passes still add up to O(n). Finding the middle, reversing, and merging are each a single pass — O(n) + O(n) + O(n) simplifies to O(n), not O(3n²) or anything worse.
    • In-place pointer rewiring costs O(1) space. No new nodes, arrays, or recursion stack are created — only a handful of pointer variables (slow, fast, prev, curr, first, second).
    • Compare against the array trick. Dumping nodes into a list and using two indices also works, but costs O(n) space — a strong tell for why the pointer-only approach is preferred here.
    • Reversal is the classic O(n) time / O(1) space pattern. Recognizing "in-place linked list reversal" as its own reusable building block is exactly what this problem is testing.

    A brute-force approach could dump every node into an array and rebuild the list with two indices, but the interview-standard fix stays entirely on pointers:

    1. Use slow/fast pointers to find the middle of the list in one pass.
    2. Cut the list at the middle, then reverse the second half in place.
    3. Merge the first half and the reversed second half by alternating nodes.
    4. Stop once the (shorter or equal) second half runs out — the first half's remaining tail terminates the list correctly.
    # Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        """
        Do not return anything, modify head in-place instead.
        """
        if not head or not head.next:
            return

        # Step 1: find the middle (slow ends at start of second half)
        slow, fast = head, head
        while fast.next and fast.next.next:
            slow = slow.next
            fast = fast.next.next

        # Step 2: reverse the second half
        second = slow.next
        slow.next = None  # cut the list into two halves
        prev = None
        while second:
            nxt = second.next
            second.next = prev
            prev = second
            second = nxt
        second = prev  # head of reversed second half

        # Step 3: merge the two halves alternately
        first = head
        while second:
            first_next = first.next
            second_next = second.next

            first.next = second
            second.next = first_next

            first = first_next
            second = second_next

    Time

    O(n)

    Finding the middle, reversing, and merging are each a single O(n) pass.

    Space

    O(1)

    Only pointer variables are used — nodes are rewired in place.
